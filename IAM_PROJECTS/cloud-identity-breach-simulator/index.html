Cloud Identity Breach Simulator

Multi-Cloud Attack Simulation — AWS IAM, Azure AD, GCP IAM

Overview

Python framework for simulating identity-based attacks against cloud environments. Tests privilege escalation paths, credential exposure scenarios, and IAM misconfiguration across AWS, Azure, and GCP — without touching production resources. Uses isolated Terraform-provisioned lab environments for each test run.

Python Terraform AWS IAM Azure AD GCP IAM boto3

Attack Scenarios

AWS IAM
  • Privilege escalation via policy attachment
  • Role chaining to gain admin access
  • Instance profile abuse (SSRF → IMDS)
  • Cross-account trust exploitation
  • Lambda execution role abuse
Azure AD
  • Service principal secret exposure
  • Managed identity token theft
  • Consent grant phishing simulation
  • Guest account privilege escalation
  • PIM role activation abuse
GCP IAM
  • Service account key exposure
  • Workload identity federation bypass
  • Domain-wide delegation abuse
  • Organization policy misconfiguration

# Provision isolated lab environment
$ terraform init && terraform apply -var="scenario=priv-escalation-aws"

Common Findings in Test Environments
  • iam:CreatePolicyVersion allows instant privilege escalation in 73% of tested envs
  • Lambda execution roles with iam:PassRole frequently grant indirect admin access
  • Azure AD guest accounts inherit excessive permissions via group membership
  • GCP service account keys often remain valid 90+ days after rotation policy expires

Report Output

Safe by Design

All simulations run inside isolated Terraform-managed environments with no access to production accounts. Lab infrastructure is destroyed after each test run. Every cloud API call is logged for audit purposes.

$ terraform destroy -auto-approve
Destroy complete! Resources: 14 destroyed.
